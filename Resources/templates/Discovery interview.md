# Discovery interview

## 📖 Context

Bruk denne malen når du oppsummerer et **discovery-intervju** med kunde, prospekt eller intern interessent.

Målet er å trekke ut:

- hvem brukeren/kunden er
- hvilke problemer som faktisk oppleves
- hva som haster mest
- hvordan problemet løses i dag
- hvilke konsekvenser problemet har for tid, kvalitet, kostnad eller risiko
- hvilke signaler som peker mot kjøpsvilje, beslutningsprosess og neste steg

Oppsummeringen skal hjelpe teamet med å forstå **behov, prioritet og kommersielt potensial** — ikke bare hva som ble sagt.

## ✍️ Summary format

Strukturer oppsummeringen i seksjonene under.

### 1. Kort sammendrag

Start med 3–5 punkt som oppsummerer det viktigste fra samtalen:

- viktigste behov/problem
- hvem som er berørt
- hvorfor dette er viktig nå
- eventuell tydelig kjøpsdriver eller risiko

### 2. Bakgrunn og kontekst

Beskriv kort:

- selskap/team/rolle
- hvilken prosess eller arbeidsflate intervjuet handlet om
- hvor i organisasjonen problemet oppstår
- relevant modenhet, systemlandskap eller organisatorisk kontekst

### 3. Mål og ønsket effekt

Beskriv hva intervjupersonen prøver å oppnå.

Skill tydelig mellom:

- operative mål
- forretningsmessige mål
- ønsket effekt for sluttbruker, team eller ledelse

### 4. Problemer og friksjon

List de viktigste problemene som kom frem.

For hvert problem bør oppsummeringen så langt som mulig få frem:

- hva som skjer i praksis
- hvor ofte det skjer
- hvem som rammes
- konsekvensen av problemet
- hvor alvorlig eller kritisk det virker

Prioriter konkrete og observerbare problemer fremfor generelle meninger.

### 5. Dagens løsning / workaround

Beskriv hvordan problemet håndteres i dag:

- manuelle steg
- systemer/verktøy i bruk
- midlertidige workarounds
- flaskehalser, dobbeltarbeid eller avhengigheter

Dette er viktig for å forstå både modenhet og implementeringsmulighet.

### 6. Sitater, signaler og indikatorer

Trekk frem formuleringer eller utsagn som er spesielt verdifulle, for eksempel:

- tydelig frustrasjon
- tydelig verdi
- konkrete krav eller forventninger
- innvendinger, usikkerhet eller begrensninger
- signaler om budsjett, timing, beslutningstakere eller intern forankring

Bruk korte, presise sitater bare når de tilfører innsikt.

### 7. Hypoteser og tolkninger

Legg inn en kort seksjon med analytiske vurderinger:

- hva som virker å være rotårsaken
- hvilke behov som er eksplisitte vs. implisitte
- hvilke mønstre som går igjen
- hva som bør verifiseres i neste samtale

Skill tydelig mellom **det som ble sagt** og **tolkningen vår**.

### 8. Produkt- og løsningsimplikasjoner

Oversett innsikten til mulige implikasjoner:

- hvilke muligheter dette peker mot
- hvilke capability-behov som ser viktigst ut
- hvilke krav, begrensninger eller avhengigheter som må tas hensyn til
- hva som eventuelt ikke bør bygges eller loves ennå

### 9. Kommersiell vurdering

Hvis relevant, oppsummer:

- hvor tydelig behovet virker
- hvor stort problemet ser ut til å være
- hvor nært dette virker knyttet til betalingsvilje
- om caset virker strategisk, taktisk eller lavt prioritert

Ikke overtolk. Vær eksplisitt på usikkerhet.

### 10. Neste steg

Avslutt med konkrete anbefalte neste steg:

- hva som bør undersøkes videre
- hvem vi bør snakke med
- hvilke hypoteser som bør testes
- hvilket materiale eller beslutningsgrunnlag som bør lages
- eventuelle salgsmessige eller produktmessige oppfølginger

## 🎨 Summary style

- Skriv kortfattet, strukturert og analytisk.
- Foretrekk tydelige seksjoner og punktlister fremfor lange avsnitt.
- Prioriter innsikt over referat.
- Skill tydelig mellom fakta, sitater og tolkninger.
- Fremhev alvorlighetsgrad, konsekvens og prioritet når det er mulig.
- Bruk konkret språk. Unngå vage formuleringer som «interessant», «spennende» eller «det ble diskutert».
- Hvis informasjon mangler, si det eksplisitt i stedet for å fylle hull med antakelser.
- Hvis intervjuet peker mot kjøpsmulighet, vis det nøkternt og evidensbasert.
- Avslutt gjerne med en kort vurdering: **Hva lærte vi, og hva betyr det?**
